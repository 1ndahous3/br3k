# br3k

Generated by `cargo api` from Rust declarations and `///` documentation. Do not edit this file.

[API index](../api/index.md) | [Core guide](../core.md) | [PE workflows](../pe_recovery.md)

Windows research primitives for the embedded br3k Python VM.

Use only for authorized, non-malicious education, research, and testing. Import feature namespaces (`proc`, `fs`, `pe`, and others) for new scripts; the root also retains older names for compatibility. This is an embedded module provided by br3k-cli/br3k-dll, not a package installed into CPython.

Addresses are integers in the address space specified by each operation; lengths and offsets are bytes unless documented otherwise. Native resources and executable addresses require valid lifetimes and matching target ABIs. Invalid pointers may crash the host rather than produce a Python exception. Most OS failures become `SystemError`; argument/state errors commonly become `ValueError` or `TypeError`. Availability depends on Windows build, access rights, target architecture, and the chosen system API backend.

`= ...` in generated signatures means optional, not a literal Ellipsis value. Omission and `None` are different: only nullable parameters accept `None`. Root and namespaced strategy enums are separately created IntEnum classes with matching values; use one namespace consistently rather than testing identity.

### FileChangeStrategy

[Source](../../lib/src/vm/api_strategy.rs#L206)

Destructive file-change operation; zeroing is not a secure-erasure guarantee.

- `DeleteFile`: Delete using the separately selected FileDeleteStrategy; the default.
- `OpenFile`: Open for writing using FileOpenStrategy and overwrite content with zeros.
- `CreateFileMapping`: Map the file for writing and zero the mapped bytes.

### FileDeleteStrategy

[Source](../../lib/src/vm/api_strategy.rs#L119)

Native file-deletion mechanism. Deletion timing still follows Windows handle/share rules.

- `NtDeleteFile`: Delete by name with NtDeleteFile; the default file-delete strategy.
- `SetInformationFile`: Set disposition using the configured SetInformation_Delete dispatch.
- `NtOpenFileDeleteOnClose`: Open with NtOpenFile and FILE_DELETE_ON_CLOSE, then close the handle.
- `NtCreateFileDeleteOnClose`: Open with NtCreateFile and FILE_DELETE_ON_CLOSE, then close the handle.

### init_sysapi

```python
init_sysapi(*, sys_api_backend: str = ..., sys_api_dispatch: dict[str, str] = ...) -> None
```

Configure the engine-wide system API backend and dispatch choices.

`sys_api_backend` accepts `Dll` (default), `DllCopy`, or `DirectSyscall`. `sys_api_dispatch` is a string-to-string mapping. Omitted entries use defaults; unknown keys, variants, or backend names raise `ValueError`. A selected call that is unavailable fails instead of retrying another variant. Configure this before creating native resources; it is not a per-object or per-call setting.

Dispatch keys and variants (default first):
- CreateProcess: NtCreateProcessEx, NtCreateProcess
- CreateThread: NtCreateThreadEx, NtCreateThread
- CreateSection: NtCreateSection, NtCreateSectionEx
- MapViewOfSection: NtMapViewOfSection, NtMapViewOfSectionEx
- UnmapViewOfSection: NtUnmapViewOfSection, NtUnmapViewOfSectionEx
- AllocateVirtualMemory: NtAllocateVirtualMemory, NtAllocateVirtualMemoryEx
- ReadVirtualMemory: NtReadVirtualMemory, NtReadVirtualMemoryEx
- QueueApcThread: NtQueueApcThread, NtQueueApcThreadEx, NtQueueApcThreadEx2
- SetInformation_Delete: FileDispositionInformation, FileDispositionInformationEx
- SetInformation_Rename: FileRenameInformation, FileRenameInformationEx

Parameters:

- `sys_api_backend`: Dll (default), DllCopy, or DirectSyscall; names are case-sensitive.
- `sys_api_dispatch`: Dispatch target names to variant names; omitted entries retain their defaults.
