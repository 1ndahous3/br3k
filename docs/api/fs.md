# br3k.fs

Generated by `cargo api` from Rust declarations and `///` documentation. Do not edit this file.

[API index](../api/index.md) | [Core guide](../core.md) | [PE workflows](../pe_recovery.md)

File I/O, native mappings, and explicit open/delete/rename/change strategies.

Native path-based operations expect Windows filesystem paths; prefer absolute paths. `create_file` can overwrite existing content, `write_bytes` truncates, and change/delete operations are destructive. Mapping and section APIs expose local addresses and owning handles, not Python streams.

Example (read-only):
```python
from br3k import fs
data = fs.read_bytes(r"C:\Windows\System32\notepad.exe")
mapping = fs.Mapping(r"C:\Windows\System32\notepad.exe")
size = mapping.size
```

### ChangeStrategy

[Source](../../lib/src/vm/api_strategy.rs#L206)

Destructive file-change operation; zeroing is not a secure-erasure guarantee.

- `DeleteFile`: Delete using the separately selected FileDeleteStrategy; the default.
- `OpenFile`: Open for writing using FileOpenStrategy and overwrite content with zeros.
- `CreateFileMapping`: Map the file for writing and zero the mapped bytes.

### DeleteStrategy

[Source](../../lib/src/vm/api_strategy.rs#L119)

Native file-deletion mechanism. Deletion timing still follows Windows handle/share rules.

- `NtDeleteFile`: Delete by name with NtDeleteFile; the default file-delete strategy.
- `SetInformationFile`: Set disposition using the configured SetInformation_Delete dispatch.
- `NtOpenFileDeleteOnClose`: Open with NtOpenFile and FILE_DELETE_ON_CLOSE, then close the handle.
- `NtCreateFileDeleteOnClose`: Open with NtCreateFile and FILE_DELETE_ON_CLOSE, then close the handle.

### FileMode

[Source](../../lib/src/fs.rs#L23)

File access and sharing flags, not creation or truncation policy.

- `Read`: FILE_GENERIC_READ access and FILE_SHARE_READ sharing.
- `Write`: FILE_GENERIC_WRITE access and FILE_SHARE_WRITE sharing.
- `ReadWrite`: Combined generic read/write access and read/write sharing.

### OpenStrategy

### RenameStrategy

[Source](../../lib/src/vm/api_strategy.rs#L181)

File rename or non-atomic copy/delete operation.

- `Rename`: Set rename information using the configured SetInformation_Rename dispatch.
- `CopyDelete`: Copy the content to the destination, then delete the original; not atomic.

### SectionMode

[Source](../../lib/src/fs.rs#L59)

Access rights requested on a section handle, separate from mapped page protection.

- `Read`: SECTION_MAP_READ.
- `Write`: SECTION_MAP_WRITE.
- `Execute`: SECTION_MAP_EXECUTE.
- `ReadWrite`: SECTION_MAP_READ and SECTION_MAP_WRITE.
- `WriteExecute`: SECTION_MAP_WRITE and SECTION_MAP_EXECUTE.

### change_file

```python
change_file(filepath: str, *, file_change_strategy: br3k.fs.ChangeStrategy | int = ..., file_delete_strategy: br3k.fs.DeleteStrategy | int = ..., file_open_strategy: br3k.fs.OpenStrategy | int = ...) -> None
```

Delete a file or overwrite its content with zeros using the selected strategy.

Defaults to `ChangeStrategy.DeleteFile`, `DeleteStrategy.NtDeleteFile`, and `OpenStrategy.NtOpenFile`. The delete/open strategies apply to their respective change modes. Zeroing is destructive but is not guaranteed secure erasure.

Parameters:

- `file_change_strategy`: Defaults to ChangeStrategy.DeleteFile.
- `file_delete_strategy`: Used only by DeleteFile; defaults to DeleteStrategy.NtDeleteFile.
- `file_open_strategy`: Used only by OpenFile; defaults to OpenStrategy.NtOpenFile.

### create_file

```python
create_file(filepath: str, *, file_mode: br3k.fs.FileMode | int) -> br3k.resource.Handle
```

Create or overwrite a file with the requested `FileMode` and return an owning handle.

The native create disposition is FILE_OVERWRITE_IF: existing content can be lost. Invalid modes raise `ValueError`, native errors `SystemError`.

Parameters:

- `file_mode`: File access/share mode, independent of creation disposition.

Create an image section from an open file handle.

`sect_mode` selects section-handle access rights; it does not change the read-only page-protection argument used by this wrapper. Returns an owning handle.

Parameters:

### delete_file

Delete the named file using `DeleteStrategy.NtDeleteFile` by default.

SetInformationFile uses the configured SetInformation_Delete dispatch. Deletion may be deferred until open handles close; native failures raise `SystemError`.

Parameters:

- `file_delete_strategy`: Defaults to DeleteStrategy.NtDeleteFile.
