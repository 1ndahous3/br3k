### ArtifactKind

[Source](../../../lib/src/pe/format.rs#L30)

Surviving PE-header pattern recognized in a byte scan.

- `MzPe`: DOS and NT signatures identify a PE header candidate.
- `NtHeaders`: NT signature and associated headers survive without requiring a DOS header.
- `FileHeader`: COFF and optional-header evidence survives without requiring signatures.
- `SectionTable`: A plausible section table survives without usable preceding headers.

### CheckStatus

[Source](../../../lib/src/pe/headers/directories.rs#L117)

Bounded structural validation status for a data directory.

- `Absent`: Directory has no declared address or size.
- `Valid`: Directory passed the implemented structural checks; not a loader certification.
- `Invalid`: Directory failed a supported structural check.
- `Unsupported`: The directory or its format is not supported by the validator.
- `FileOnly`: The directory requires file-only interpretation rather than mapped-memory validation.

### DirectoryRecoveryStatus

[Source](../../../lib/src/pe/headers/directories.rs#L15)

Outcome of salvaging a data-directory entry from surviving header evidence.

- `Restored`: Directory metadata passed supported checks and was restored.
- `Invalid`: Directory contents or range failed validation.
- `Unsupported`: Directory format has no supported salvage validation.
- `FileOnly`: Directory refers to file-only data that cannot be recovered from a mapped capture.
- `HeaderOverlap`: Directory range conflicts with the reconstructed header area.

### SectionRawLayout

[Source](../../../lib/src/pe/image.rs#L148)

File-offset policy when converting mapped sections to file layout.

- `MappedOffsets`: Keep raw section offsets aligned with their virtual addresses.

Source of section-layout evidence used for synthetic header reconstruction.

- `MemoryRegions`: Sections were inferred from memory-region boundaries and protections.
